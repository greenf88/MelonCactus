## Actual browser observations

The loaded `/e3ffe1d2b830bc05/script.js` returned 200. Its code skips pageviews when `navigator.webdriver` is true or the user agent contains `Headless`. A default automated headless run therefore loaded the script but sent **no** pageview and could not prove the opt-out. The recorded comparison below used visible Chromium 153 with the automation-detection Blink flag disabled (`navigator.webdriver: false`, ordinary Chrome user agent). The POSTs came from the loaded Vercel script in that browser, not from a test-created request. This test adjustment and Preview authentication limit inference to the tested browser/deployment.

The first captured POST targeted the real Preview endpoint `/e3ffe1d2b830bc05/view` with `Content-Type: application/json`, HTTP 200, and `Referer` equal to the Preview **origin only**. Its JSON contained `o: "https://…/privacy"`, `dp: "/privacy"`, `sv: "0.1.3"`, `sdkn: "@vercel/analytics/next"`, `sdkv: "2.0.1"`, a timestamp and `r: ""`. The genuine NL POST had `o: "https://…/nl/privacy"`, `dp: "/nl/privacy"` and the same origin-only `Referer`. No contact marker was present in those captured pageviews; the no-send result during opt-out is supported by the request log, not by a manufactured request.

An independent temporary local browser profile was opted out, closed, then reopened on the local production build: the stored `off` and visible off status survived the browser restart, and no Analytics script mounted. The temporary profile was removed after the test. The Preview browser also kept `off` across reload and between EN/NL tabs. Keyboard focus plus Enter on the EN control disabled measurement. At 390 × 844 and 1440 × 900 on NL `/nl/privacy`, the control rendered without horizontal overflow; an axe check scoped to the control reported 0 violations and 0 incomplete checks. The Preview Toolbar overlay is separate from the site control and does not exist on Production.
