# Internal dossier numbering — enquiries and projects

This is an internal filing convention, not a public customer claim or an automated website feature.

- Format: `YYMMNNN`, displayed optionally as `YY-MM-NNN`. The owner selected **`2610001`** (`26-10-001`) for the first project in October 2026. Reserve that number for that project; do not put a real client name or project record in this repository. If the project has not yet been registered, the private register must show the reservation before another case receives an October number.
- Use **one shared monthly sequence** for both enquiries and direct projects. After the reserved `2610001`, the next October 2026 case receives `2610002`. Assign the next unused number when an enquiry or direct project is first registered. Reset the three-digit sequence to `001` in a new calendar month; the `YYMM` prefix distinguishes months.
- If an enquiry becomes a project, keep its original dossier number. Do not issue a second project number. Never recycle a number after a declined, withdrawn or duplicate enquiry; instead record its status in the private register.
- Keep the register outside this source repository. Record only the number, receipt date, current status and a pointer to the restricted business mailbox/project file. Do not commit names, email addresses, enquiry contents or project materials to Git.
- This convention does **not** itself generate or reserve a number. Until an access-controlled register with atomic allocation exists, one designated person must issue numbers sequentially and check the register before assigning each one. The public contact form and Resend email remain unchanged.
- A dossier number does not extend any retention period. Apply the enquiry or project retention rule to the related register entry and its link to identifiable records; retain a number-only audit trail only if justified separately.
